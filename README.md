# Counterparty Agent

ИИ-помощник для проверки и сравнения контрагентов по уже доступному отчёту.
Агент ищет компанию по ИНН, ОГРН или названию, выделяет подтверждённые сигналы,
показывает пробелы в данных и отвечает на уточняющие вопросы в рамках одной
сессии.

> Сейчас это только компактный scaffold: структура, зависимости и TODO. Агент
> ещё не реализован и приложение пока не запускается.

## Основные решения

- **Оркестрация:** явный `LangGraph StateGraph`, без `Deep Agents` в MVP.
- **Логика:** расчёты, сравнение, похожие группы и проверки выполняет Python;
  LLM формулирует ответ по готовым фактам.
- **Grounding:** каждый вывод должен ссылаться на существующий `evidence_id`.
- **Память:** LangGraph checkpointer хранит контекст только выбранной сессии;
  новая сессия не получает старый контекст.
- **Данные:** вложенный JSON — основной demo-формат; CSV — fallback.
- **Окружение:** Python 3.12 и `uv`; точные версии фиксируются в `uv.lock`.

Подробнее: [архитектурное решение](docs/architecture.md) и
[контекст продукта](CONTEXT_PACK.md).

## Банковский «Светофор»

`zskRiskLevel` — готовая оценка банковского скоринга на дату проверки. Модель
скоринга и её факторы не раскрываются, поэтому агент **не пересчитывает цвет и
не придумывает его объяснение**.

| Цвет | Значение в интерфейсе |
|---|---|
| `GREEN` | надёжный контрагент |
| `YELLOW` | требует внимания |
| `RED` | в зоне риска |
| `GREY` | нет данных для оценки |

Светофор показывается отдельно от найденных агентом фактов и качества данных.
`GREY` не равен низкому риску, а `GREEN` не является гарантией безопасности
конкретной сделки. Поле `baseInfo.riskLevel` также хранится отдельно и не
смешивается со светофором без подтверждённой методики.

Если `zskRiskLevel` отсутствует в ответе источника, backend сохраняет исходное
значение как `null`, а интерфейс может показать `GREY` с подписью «нет данных».
Так отсутствие поля не маскируется под явно полученную оценку банка.

## Данные отчёта

Контракт `GetFullReportResponse` содержит шесть крупных блоков:

1. общие сведения и статус;
2. учредители, руководство, связи, ОКВЭД и налоги;
3. суды, исполнительные производства, проверки и лицензии;
4. положительные и отрицательные репутационные факторы;
5. финансы и коэффициенты;
6. госзакупки.

JSON содержит Mongo Extended JSON-значения (`$date`, `$numberLong`), которые
нужно преобразовать до Pydantic-валидации. Исходные snapshots могут содержать
PII, поэтому они не коммитятся и не логируются целиком.

DOCX-контракт и реальные snapshots местами расходятся в именах и enum-значениях
(например, `cofounders[].isActive` против `active`). Source-адаптер нормализует
такие aliases, но сохраняет исходное поле и не отбрасывает неизвестные значения.

## Планируемый поток

```text
запрос
→ определить intent и идентификаторы
→ найти/уточнить компанию
→ загрузить канонический snapshot
→ детерминированный анализ
→ сравнить или построить похожую группу при необходимости
→ LLM формулирует ответ
→ evidence validator
→ сохранить компактный контекст сессии
```

## Стек

| Задача | Выбор |
|---|---|
| Управление проектом | `uv`, `uv_build`, Python 3.12 |
| Workflow и память | `langgraph`, SQLite checkpointer |
| LLM | `langchain-core`, `langchain-openai`, OpenAI-compatible Qwen/GPT-OSS |
| Контракты | Pydantic v2, `pydantic-settings` |
| API и streaming | FastAPI, Uvicorn, AG-UI/SSE |
| Источники | стандартный JSON/CSV, `httpx` для будущих API |
| Поиск по названию | RapidFuzz |
| Проверки | pytest, pytest-asyncio, Ruff, mypy |

В MVP не нужны vector DB, embeddings, RAG, Redis, брокер задач, `Deep Agents`
и отдельный LLM на каждый раздел.

## Как разделить работу в команде

- **Данные:** `models.py`, `sources.py`, fixtures и качество входных данных.
- **Аналитика:** `analysis.py`, правила, сравнение и похожие группы.
- **Агент/backend:** `graph.py`, память, LLM и grounding flow.
- **API/frontend:** `app.py`, AG-UI, виджеты и streaming.
- **QA:** тестовые вопросы, expected evidence и сценарии отказа.

## Первый запуск после установки uv

```bash
uv sync
uv run pytest
```

Первый `uv sync` создаст `uv.lock`; его нужно проверить и закоммитить. После
реализации `app.py` команда запуска будет добавлена сюда. Lock-файл вручную не
редактируется.
