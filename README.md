# Проверка контрагентов

Локальное рабочее пространство: найти компании, сравнить отчёты, оставить
кандидатов в отборе и провести углублённую проверку внутри проекта.

## Запуск

```bash
uv sync
uv run python src/main.py
```

Открыть [localhost:8000](http://127.0.0.1:8000). Остановить сервер — `Ctrl+C`.
Если порт занят: `COUNTERPARTY_PORT=8011 uv run python src/main.py`.
Активировать `.venv` для команд `uv` не нужно.

При первом запуске скопируйте `.env.example` в `.env` и укажите
`COUNTERPARTY_SNAPSHOT_JSON_PATH`. Ключ модели задаётся только через
`COUNTERPARTY_LLM_API_KEY`. Текущее локальное подключение сохранено;
его адрес и модель настраиваются через `COUNTERPARTY_LLM_BASE_URL` и
`COUNTERPARTY_LLM_MODEL`. Используется совместимый Chat Completions API.
Карточка и сравнение по явным реквизитам работают без ключа;
понимание свободного текста и AI-диалог требуют подключения.
`/api/health` показывает доступность данных и AI, но не секреты.

Собранный интерфейс включён в репозиторий: для обычного запуска Node не нужен.
После изменения frontend:

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm build
pnpm test
```

Для разработки нужен Node 22+ и pnpm. Vite собирает UI в
`src/counterparty_agent/ui/build`; FastAPI раздаёт его тем же процессом.

## Как пользоваться

1. Ввести ИНН, ОГРН, название или свободную просьбу найти/сравнить компании.
   Несколько явных реквизитов можно разделить `;`.
2. При неоднозначности подтвердить компанию по реквизитам.
3. Сравнить показатели: фильтр по названию/светофору, «Только различия», ручной отбор.
4. Нажать показатель для просмотра источника; название — для карточки компании.
5. Спросить помощника: «У кого есть убыток?», «Какие пробелы в данных по группе?».
6. Сохранить проект, указать цель, при необходимости оставить финалистов в отборе.
7. Запустить план, приложить документ, связать его с открытым вопросом.
8. Просмотреть изменения резюме и явно подтвердить их. Автоодобрения сделки нет.

Карточка открывается с краткой сводки: реквизиты, оценка банка, финансовые показатели,
записи для внимания и ограничения данных. Полный текст доступен в раскрывающихся
разделах; кнопка «Раскрыть все» показывает весь отчёт. Счётчики обозначают записи,
а не независимые риски. Банковский светофор не объясняется этими записями.
В разделе «Финансы» доступны виджеты и линейный график годовых значений с выбором
показателя и переключателем «Линия / Столбцы». Пропуски остаются разрывами.
Сравнение также начинается с краткой матрицы: статус, выручка, прибыль, сигналы
внимания и ограничения. Полные показатели раскрываются по темам. Раздел «Группа
в цифрах» показывает распределение банковских оценок и наличие финансовых данных
по всей группе. Нажатие на значение или элемент сводки открывает источники.
Фильтры и страницы применяются к обеим матрицам, не меняя исходные номера компаний;
серый, отсутствующий и неизвестный банковский сигнал фильтруются отдельно.
Графики не назначают валюту неизвестным суммам и не создают финансовый рейтинг.

Примеры команд: «Сравни ИНН …; ИНН …», «Подробнее про вторую»,
«Добавь к сравнению ИНН …», «Покажи сравнение», «А почему 1 требует внимания?».
Вопрос по номеру относится к исходному порядку сравнения. В ответе на вопрос о
причинах цвета помощник разделяет банковскую оценку и отдельные сигналы по данным
этой компании: сигналы не объявляются причинами закрытого банковского скоринга.
В проектном чате конкретную компанию надёжнее указывать по ИНН;
порядковые ссылки используйте в чате таблицы.

В чате проверки свободный текст сначала разбирает LLM-роутер: поиск, сравнение,
добавление в группу, вопрос по отчёту или уточнение. Например, «Из-за чего этот
контрагент надёжен?» и «А каккие есть судебные дела?» относятся к текущей карточке.
Код проверяет извлечённые реквизиты и исполняет разрешённое действие. Затем отдельный
выбор фактов формирует ответ по источникам. Точный ИНН, явный список реквизитов, кнопки и
восстановление страницы не вызывают модель. Ошибка роутера сохраняет выбор и
показывает причину отказа; целый непонятый вопрос не используется как имя компании.
Без AI остаётся ограниченный ручной режим явных команд, не полноценный разбор речи.

Лимит десяти участников снят. Проверены группы до 100 компаний.
Таблица показывает до шести колонок на странице, сохраняя весь состав.
Это не обещание неограниченной производительности: запрос ограничен 12 000 символами,
данные — подключённой выборкой. Финансового рейтинга и автоматического победителя нет.

## Три уровня решения

| Уровень | Что выполняет код | Где используется AI |
|---|---|---|
| Отчёт и сравнение | Поиск, расчёты, периоды, пропуски, таблица | Только понимание свободного запроса |
| Диалог | Проверка адресата, каталог фактов, сборка текста, ссылки | Намерение и выбор релевантных фактов |
| Сохранённый проект | Три ограниченных чтения, документы, diff и подтверждение | Выбор тем плана и цитат |

Модель не пишет произвольное заключение: после маршрутизации возвращает ID из каталога,
а сервер собирает проверенные формулировки. Это снижает риск выдуманных чисел,
но не гарантирует релевантность выбора — для неё нужны отдельные оценки.

`zskRiskLevel` — неизменяемый внешний банковский сигнал: зелёный — надёжный,
жёлтый — требует внимания, красный — в зоне риска, серый — нет данных для оценки.
Он не пересчитывается и не объясняется собственными факторами приложения.
Отсутствующий сигнал сохраняется отдельно от явно переданного `GREY`.
Отсутствие данных не означает отсутствие риска.

## Карта репозитория

```text
src/main.py                       единый запуск
src/counterparty_agent/
  config.py                       настройки из окружения
  models.py                       общие контракты отчёта и evidence
  query.py                        извлечение реквизитов, exact/fuzzy-поиск
  data/                           чтение JSON, нормализация, индексы, provenance
  analytics/                      правила по разделам и сравнение
  ai/                             роутер намерения, транспорт, каталоги и выбор фактов
  workflow/                       явный LangGraph, маршруты и память сессии
  api/                            HTTP, проекции, жизненный цикл и владение
  projects/                       проекты, план, документы, чат и резюме
  ui/build/                       готовая сборка интерфейса
frontend/src/
  workspace/                      оболочка, состояние и запросы
  comparison/                     таблица, карточка, форматирование
  projects/                       интерфейс сохранённого проекта
  components/                     чат, источники и общие элементы
  styles/                         тематические стили
tests/                            Python-регрессии и интеграционные сценарии
benchmarks/                       независимый синтетический генератор
docs/                             архитектура и фактический статус
data/                             локальные отчёты; не коммитятся
```

Импорты ведут прямо к реализации: источник — `data/repository.py`, анализ —
`analytics/core.py`, сравнение — `analytics/comparison.py`, граф —
`workflow/builder.py`, HTTP и запуск — `api/routes.py`, LLM-транспорт —
`ai/transport.py`. `ai/router.py` проверяет JSON намерения, `workflow/semantic.py`
исполняет его в границах сессии. Отдельных файлов-переэкспортов нет;
`__init__.py` обозначают пакеты.

Стек: Python 3.12, uv, FastAPI, Pydantic, LangGraph, SQLite для памяти,
RapidFuzz, Decimal; React, TypeScript, Vite, Recharts, базовые Alfa Core Components.
SQLite хранит сессии и проекты, **не базу карточек контрагентов**.
Данные по-прежнему читаются из JSON; CSV остаётся резервным направлением,
отдельного CSV-адаптера в рабочем runtime нет. БД отчётов и MCP не добавлены.
