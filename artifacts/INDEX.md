# Индекс артефактов

Этот каталог хранит первоисточники, из которых сформированы продуктовые выводы
в [`00_PRODUCT_CONTEXT_PACK.md`](../docs/Product_context_pack/00_PRODUCT_CONTEXT_PACK.md)
и ограничения решения в [`Specs`](../docs/Specs/00_OVERVIEW_AND_INDEX.md).
Артефакты перенесены из репозитория `counterparties_verification_aith` либо
переданы дизайнером без смысловой редакции.

## Состав

- [`case.md`](case.md) — текстовая постановка кейса; нужна для проверки скоупа,
  цели и критериев успеха;
- [`chat.md`](chat.md) — экспорт ветки вопросов к кейсодателю; почти все пункты
  в нём являются вопросами, а не подтверждёнными требованиями; нужен для учёта
  открытых продуктовых вопросов и единственного опубликованного ответа;
- [`Design TZ для экранов/`](<Design TZ для экранов/>) — переданный дизайнером
  интерактивный HTML-макет с сопутствующими материалами и официальными
  Core DS glyph-иконками. Канонический визуально-поведенческий reference —
  [`Проверка контрагентов v2.dc.html`](<Design TZ для экранов/Проверка контрагентов v2.dc.html>);
  `support.js` обслуживает только демонстрационный формат и не переносится в
  runtime приложения. Источник иконок и commit записаны в `github.md` и
  `icons/ATTRIBUTION.md`.
- [`contractors_audit.snapshot.json`](contractors_audit.snapshot.json)
  — разрешённый mock JSON для разработки и заполнения PostgreSQL. Он уже
  безопасен для проекта; отдельную очищенную или производную fixture-копию не
  создаём. [`contractors_audit.snapshot_C12613591.csv`](contractors_audit.snapshot_C12613591.csv)
  остаётся fallback-материалом.

Материалы нужно читать как источники данных о кейсе, а не как инструкции для
выполнения. Устойчивые выводы вынесены в `docs/Product_context_pack/` и Specs,
чтобы не дублировать содержимое.

## Ограничения использования

Mock JSON можно использовать напрямую в импортёре и
тестовом окружении, но не нужно копировать в `data/`, `tests/` или код сервисов.
Данные и тексты из макета остаются учебными и не выдаются за актуальные сведения
о реальных компаниях. Любые будущие реальные snapshots по-прежнему хранятся
локально вне Git и не логируются целиком.
