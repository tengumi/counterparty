# 06. Frontend и интеграция агентного чата

Версия 1.1 · 05.09.2026. [Индекс](00_OVERVIEW_AND_INDEX.md) · [Дизайн](07_DESIGN_AND_UX.md) · [Контракты](10_SYSTEM_CONTRACTS.md).

## 1. Стек

React + TypeScript strict + Vite; React Router; TanStack Query для REST; `@alfalab/core-components` и `@alfalab/icons-glyph`; CSS Modules для компоновки. Версию React выбирать в пределах peer dependencies закреплённой версии Core DS. Не обновлять React отдельно от проверки DS и assistant-ui.

Готовая основа чата — `@assistant-ui/react` с Assistant Transport runtime. Backend использует Python assistant-stream. Использовать доступные primitives сообщений, composer, действий и доступности; не писать свой chat state machine и parser потоковых chunks. Конкретные imports/codec фиксируются по V01. `useStream` LangChain, AG-UI и Open WebUI не являются обязательными зависимостями встроенного чата.

Функциональность assistant-ui соединяется с визуальными компонентами Альфы через адаптеры/hooks/composition. Проверить refs, обработку клавиатуры и forwarding props; не обещать универсальный asChild для любого Core DS компонента. Если Textarea нельзя напрямую встроить в primitive, связать её с runtime через документированный hook, сохранив одно состояние composer.

## 2. Маршруты и состояние

Основные поверхности: `/checks` (S1) и `/checks/:projectId` (S2). Выбранный чат адресуется `/checks/:projectId/chats/:threadId`; это состояние той же поверхности S2. Панель материалов, источник, сравнение и решение — состояния внутри S2. Сохранять выбранный материал, scroll и черновик при открытии/закрытии панели. Не добавлять отдельные страницы «Агент», «План», «Досье», «Сравнение».

| Состояние | Владелец |
|---|---|
| Сообщения, run status, activity, streamed analysis | assistant-ui runtime, данные от Agent Service |
| Проекты, документы, условия, сохранённые решения | TanStack Query, REST source of truth |
| Открытая панель, выделение, draft | Локальное React-состояние; draft при необходимости в sessionStorage без секретов |
| Полная память агента | Сервер; не восстанавливается из localStorage |

Не держать три независимых копии messages в Query, глобальном store и assistant-ui. При обновлении artifact/document/context version инвалидировать точные REST keys. Отдельный Redux/Zustand не нужен до появления конкретной проблемы.

## 3. Транспорт и команды

RPC отправляется на `/rpc/agent/chat`. Подключить Assistant Transport runtime и state converter; стандартные команды библиотеки отображать на прикладные команды из 10. Браузер не передаёт авторитетные system prompt, tools, model endpoint или API keys. Параметры библиотечного state в запросе рассматриваются только как клиентская проекция; сервер восстанавливает память из своей БД.

User message получает `client_request_id`; сохраняется pending/delivered/error состояние. При повторе с тем же ID не дублировать сообщение или запуск. Пока run активен, вводить и отправлять follow-up можно; новая реплика сразу сохраняется сервером и показывает queued/applied. Кнопка «Остановить» остаётся отдельной cancel-командой. Уход со страницы только отключает подписку.

На открытии проекта: REST загрузка доступных данных и public conversation state → определить активный run → восстановить подписку, если он ещё работает. Уже завершённый run отрисовывается из сохранённого результата. Reconnect не отправляет заново add-message. Обрыв сети показывать отдельно от завершения/отмены агента.

## 4. Материалы и структурированный UI

Регистрируем фиксированные React-компоненты для известных типов: `company_reference`, `evidence_reference`, `analysis`, `question`, `comparison_reference`, `document_reference`, `activity`. Сервер выдаёт типизированные данные, а не произвольный React/HTML-код от модели.

Номерная ссылка в ответе открывает source panel. «Обсудить» добавляет ссылку в composer с названием компании, полем и периодом; она удаляема и не отправляет сообщение сама. Backend получает evidence_ref, а не только выделенный пользователем текст.

Comparison показывает таблицу компаний по строкам; 2–20, демо пять. Детальные значения и длинные названия раскрываются. После обсуждения сравнения сохраняются выбранные кандидаты и сортировка. Цена/аванс — из пользовательских условий; сведения о компании — из report snapshot.

Документы прикрепляются через REST attachment adapter; уже созданные артефакты — через выбор версии из материалов проекта. Для файла: сначала upload/status, затем в команду агенту передаётся document_id. Обновление состояния файлов — polling с остановкой при terminal status или серверное событие по готовому механизму; не создавать отдельный websocket ради статуса одного файла.

## 5. Отображение фактов и ошибки

Date/year/unit/currency показываются по contract, Decimal-строки форматируются без потери точности. Unknown ≠ 0. Bank risk и ЗСК разные поля. Markdown очищается; arbitrary HTML выключен, ссылки проверяются. Tool failures показываются понятным действием и возможностью повтора, не traceback.

AI неработоспособен — доступны материалы и сравнение. Файл не распознан — доступен оригинал/повтор/вставка текста. Устаревшая рекомендация помечается до фиксации решения. Нет «Сохранено» до подтверждения сервера. При удалении проекта UI останавливает подписку и очищает кеш этого проекта.

## 6. Наблюдаемость для пользователя

Одна строка текущего действия и раскрываемое «Что проверено». События инструмента связываются с evidence/documents. Не отображать chain-of-thought, все аргументы MCP, токены, сырой graph state, фиктивные проценты прогресса. Текстовые этапы переводятся в продуктовый язык; статус не зависит от генерации моделью красивой фразы.

## 7. Качество и приёмка

- Поведение экранов и тексты соответствуют 07, контрактам — 10.
- Пятикомпанейное сравнение работает в текущем проекте; макет на 20 реализуем.
- Стриминг текста не дёргает пользовательский scroll, если он читает выше; новая активность обозначена.
- При выборе источника сохраняются composer и позиция ответа.
- Клавиатура, видимый фокус, подписи иконок, screen-reader сообщения об этапах; не объявлять каждый токен.
- Mobile 390 px, tablet 1024, desktop 1440; открытая панель не сжимает разговор до нечитаемой полосы.
- TypeScript strict, проверка сборки, линтер; один сквозной браузерный сценарий с разрывом соединения и восстановлением.
- Не выдавать демонстрационную оболочку за production-интерфейс Альфа-Бизнеса.

## 8. Новые элементы 1.1

В шапке/компактном списке проекта — чаты с названием, последней активностью и состоянием (работает/нужны сведения/готов). «Новый чат» не создаёт новый проект. При переключении сохраняются thread_id, сообщения, draft и выбранные вложения каждого чата; активный run в другом чате продолжает работу. Не объединять pending messages разных threads.

Composer menu: «Загрузить файл», «Прикрепить материал проекта». Выбор артефакта показывает название, версию, источник-чата и дату. Плашка удаляема до отправки; нажатие открывает preview. Поддерживается прикрепление выделенного фрагмента/раздела. Техническое слово artifact_id в UI не показывать.

Во время tools composer доступен: placeholder «Добавьте уточнение — учту после текущего действия». Новый bubble появляется с «Уточнение отправлено», затем «Ожидает обработки» / «Уточнение учтено». Статус delivered не означает applied. Ошибка приёма предлагает повторить с тем же request ID.

Если assistant-ui runtime ставит команду в локальную очередь до завершения текущего HTTP-request, стандартной отправки недостаточно. Использовать доступный runtime adapter/custom composer handler для немедленного POST follow-up и reconciliation сообщений со stream. Библиотечный streaming parser не переписывать. Native interruption не обещается.

Trace skills: отдельная строка activity «Использую навык „Чтение таблиц“»; раскрытие показывает файл, лист/диапазон, статус и результат. Не показывать raw SKILL.md/prompts. При ошибке skill видно, что конкретно не удалось прочитать. Сессии называются «Чаты»; статус авторизации не смешивается с ними.
