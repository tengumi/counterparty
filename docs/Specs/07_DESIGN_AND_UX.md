## 1. Задача, пользователь и фиксированные решения

Предприниматель приходит с деловым вопросом: «Почти выбрал поставщика. Готов ли я с ним работать и на каких условиях?». У него могут быть только ИНН и сомнение, либо уже предложение, договор и переписка. Агент помогает сформулировать вопрос, сопоставляет сведения и условия, запрашивает недостающее и предлагает обоснованный вывод. Окончательное решение фиксирует пользователь.

Результат дизайна — два основных экрана и набор состояний одной панели материалов. Чат — основная рабочая поверхность. Отчёт, документы, сравнительная таблица и итог — доступные из него материалы. Поиск по рынку, CRM и управление закупками не проектируются.

| ID | Продуктовое решение | Конкретное выражение в интерфейсе |
|---|---|---|
| R01 | Начать можно без настройки проекта | единое поле «Что хотите выяснить о контрагенте?» на первом экране |
| R02 | Работа продолжается между визитами | автоматически сохранённая проверка: разговор, компании, файлы, условия и итог |
| R03 | Основной вход — вопрос об одном контрагенте | чат с уточнением цели, без обязательной таблицы |
| R04 | Несколько контрагентов допустимы в том же проекте | «Добавить компанию» и «Сравнить»; поддержка 2–20 компаний, демо на 5 |
| R05 | Агент снимает работу по выбору разделов | сам выбирает обращения к данным; показывает краткий ход проверки, без обязательного утверждения плана |
| R06 | Ответ должен помогать определиться | карточка «Вывод по вашей задаче» и кнопка «Зафиксировать решение» |
| R07 | Проверка может закончиться без загрузки файлов | полноценный короткий путь; документы запрашиваются только для значимого неизвестного |
| R08 | Основания доступны по запросу | номерная ссылка в ответе → соответствующий фрагмент панели |
| R09 | Пользователь не должен заново объяснять ситуацию | компактное резюме «Что уже известно» при возвращении, сохранённые условия |
| R10 | Технические детали скрыты от предпринимателя | в текстах нет dossier, evidence, tool call, MCP, токенов, reasoning, decision memo |

Термин в UI — «Проверка». Он обозначает проект вокруг одной задачи, а не одну компанию: «Поставка оборудования к 20 сентября». В проверке несколько сохраняемых чатов. Первый создаётся автоматически, дополнительные — кнопкой «Новый чат». Общие материалы проекта доступны из любого чата; история сообщений и уточнения у каждого свои. Папки и вложенные проекты не требуются. Рекомендации, уточнения и многошаговые действия выполняются одним помощником, без переключателя «чат / агент».

## 3. Информационная архитектура и композиция

Два маршрута: S1 «Мои проверки» и S2 «Проверка». Все остальные поверхности открываются поверх S2, без потери разговора.

- S1: заголовок → поле начала разговора → список прошлых проверок.
- S2: компактная шапка → лента разговора → закреплённое поле сообщения.
- P1: одна правая панель «Материалы»; внутри компании, условия, файлы, итог. Одновременно открыт только один подробный материал.
- C1: сравнение — расширенное состояние P1, доступное при двух и более компаниях.
- D1: форма решения — состояние P1, не отдельный модуль.
- Подключение внешнего AI — отдельный опциональный макет X1 вне основного прототипа.

Desktop 1440×900: демонстрационная банковская навигация шириной 224 px; рабочая область занимает остаток. При закрытой панели ширина текста чата до 760 px, по центру. Обычная панель — 400 px; при ширине области менее 1000 px панель перекрывает чат, а не сжимает его. Для сравнения панель разворачивается на всю рабочую область с кнопкой «К разговору»; состояние чата сохраняется.

Tablet 1024×768: банковская навигация свёрнута; материалы открываются поверх чата. Mobile 390×844: панели становятся полноэкранными с кнопкой «Назад», строка ввода остаётся доступной с клавиатурой. Сравнение — таблица: компании по строкам, показатели по столбцам; горизонтальный скролл показателей и закреплённый столбец названия компании. Не показывать три колонки одновременно.

Если банковский shell не предоставлен, нарисовать нейтральную демо-оболочку: логотип/название Альфа‑Бизнеса и один выбранный пункт «Проверка контрагентов». Не выдавать её за точную копию действующего интернет-банка.

## 4. S1 — начать или продолжить проверку

| ID / элемент | Содержание и расположение | Действие и результат | Состояния / приёмка |
|---|---|---|---|
| S1-01 Заголовок | «Проверка контрагентов»; под ним «Разберитесь, готовы ли вы работать с компанией и на каких условиях» | нет действия | никаких маркетинговых карточек, KPI и дублирующего приветствия |
| S1-02 Поле задачи | placeholder «Напишите вопрос или вставьте ИНН»; кнопки «Прикрепить» и «Отправить» | первая отправка создаёт сохранённую проверку с первым чатом и переводит в S2 | можно начать текстом без ИНН; можно только ИНН или файлом; пустая отправка недоступна |
| S1-03 Примеры | две текстовые кнопки: «Хочу проверить поставщика»; «Хочу сравнить компании» | вставляют редактируемый текст, не отправляют автоматически | одинаковый вес; сравнение не создаёт другой тип проекта |
| S1-04 История | строки: название, последняя активность, один статус | клик открывает S2 в сохранённом месте | пусто: «Здесь появятся ваши проверки»; поиск показывать от 6 записей |
| S1-05 Продолжение | у записи со статусом «Нужны сведения» краткая подпись, например «Ждём подтверждение наличия товара» | открывает разговор у последнего незакрытого вопроса | пользователь понимает, зачем возвращаться, не читая всю историю |
| S1-06 Меню записи | «Переименовать», «Удалить» | переименование inline; удаление с подтверждением «Удалить проверку и её материалы?» | предупреждение об удалении разговора, файлов и итога; отмена безопасна |

Название создаётся автоматически по вопросу; если известен только ИНН — «Проверка · [название компании]». Пользователь может изменить его. Статусы проекта: «В работе», «Нужны сведения», «Решение записано». Статус риска компании сюда не переносить.

## 5. S2 — разговор и работа агента

| ID / элемент | Содержание и расположение | Действие и результат | Состояния / приёмка |
|---|---|---|---|
| S2-01 Шапка | «Все проверки»; название; «Сохранено»; кнопка «Материалы» | назад в S1; название редактируется; кнопка открывает P1 | ошибка сохранения: «Не удалось сохранить» + «Повторить»; черновик не исчезает |
| S2-02 Компании | под шапкой одна компактная строка: первая компания, «ещё N»; «Добавить» | открывает список/форму добавления в P1 | при 2+ появляется «Сравнить»; при 20 «Добавить» недоступно с пояснением лимита |
| S2-03 Сообщение клиента | обычный текст, вложения, время по запросу | открыть вложение | не превращать каждую реплику в карточку с рамкой |
| S2-04 Уточнение | одна реплика, максимум два связанных вопроса; например «Оплата до поставки или после? Насколько критичен срок?» | свободный ответ или короткие варианты «Аванс», «После поставки», «Ещё не решили» | уточняет только отсутствующее; если ответ уже в документе — предлагает его подтвердить |
| S2-05 Ход работы | одна строка «Сопоставляю условия оплаты и финансовые сведения»; раскрытие «Что проверено» | раскрытие показывает выполненные действия, источник и статус | можно остановить; не показывать chain-of-thought, JSON, фиктивные проценты и таймеры |
| S2-06 Ответ | сначала смысловой вывод, затем 2–4 основания с номерными ссылками, затем следующий вопрос/действие при необходимости | ссылка открывает P1-03; текст можно выделить и скопировать | длинные подробности свёрнуты; нет обязательного количества «главных рисков» |
| S2-07 Запрос подтверждения | «Наличие товара не подтверждено. Прикрепите письмо или документ, если он у вас есть»; «Прикрепить», «Документа нет» | загружает файл в этот вопрос либо сохраняет неизвестное | отсутствие документа не блокирует диалог и не считается отказом клиента от сервиса |
| S2-08 Контекстная ссылка | выделение одной строки отчёта/ячейки → «Обсудить» | в поле сообщения добавляется удаляемая плашка «Капитал · Компания А · 2025» | прикрепление не запускает отправку; агент получает точную ссылку на выбранный факт |
| S2-09 Вывод по задаче | карточка внутри разговора: «Вывод по вашей задаче», рекомендация, основания, незакрытые условия; «Зафиксировать решение» | открывает D1 с предложением, которое можно изменить | агент вправе рекомендовать, но не помечает рекомендацию как принятое решение |
| S2-10 Ввод | многострочный composer: текст, прикрепление, плашки контекста, отправка/остановка | Enter отправляет, Shift+Enter — перенос; на mobile отправка кнопкой | сообщение не теряется при открытии панелей; при работе инструмента можно отправить follow-up; принятие и применение уточнения показаны отдельно |
| S2-11 Возвращение | при первом открытии старой проверки компактный блок «Остановились на…» с одним открытым вопросом | «Продолжить» ставит фокус в composer | не отправляет автоматический запрос и не создаёт новую проверку |
| S2-12 Граница помощи | под composer «AI может ошибаться. Проверяйте основания; решение принимаете вы»; ссылка «Как работает помощник» | открывает короткое объяснение источников, ограничений, хранения и управления материалами | одно постоянное пояснение; не требовать повторное согласие на каждую реплику |

Поведенческая норма для сценариста: если вопрос закрывается доступными сведениями, агент отвечает и предлагает записать решение. Не вынуждать пользователя проходить многошаговую процедуру. Если уточнение может изменить вывод — агент объясняет, зачем спрашивает. Контекст из предполагаемых банковских систем нельзя показывать как автоматически известный: в MVP источник условий — пользователь или его файл.

## 6. P1 — материалы, основания и документы

P1 по умолчанию открывается списком из четырёх сворачиваемых групп: «Компании», «Условия», «Документы», «Итог». Это содержимое одной панели, а не четыре верхнеуровневых раздела. При открытии конкретного элемента группы заменяются его содержимым; сверху «К материалам», справа закрытие. Из основания доступен один дополнительный уровень первоисточника; кнопка назад сохраняет предыдущий экран панели.

| ID / элемент | Что рисовать | Поведение и приёмка |
|---|---|---|
| P1-01 Компании | список названий и ИНН; текущая компания отмечена текстом; «Добавить компанию» | клик открывает P1-02; удаление из проекта через меню с предупреждением о зависимых выводах; исторические ответы остаются помечены «Компания удалена из проверки» |
| P1-02 Сведения | название, ИНН, дата среза; два разных индикатора; разделы «Финансы», «Суды», «Взыскания», «Деятельность и разрешения», «Другие сведения» | разделы раскрываются по запросу; показывать только реально доступные данные; строка имеет «Обсудить» |
| P1-03 Основание | точное значение/фрагмент, компания, период, откуда взято, дата среза, доступный контекст | возврат к исходному ответу без потери прокрутки; если есть только JSON-поле — «Источник: предоставленный отчёт», без фиктивной ссылки ФНС |
| P1-04 Условия | редактируемые строки: роль компании, предмет, сумма, оплата, срок, приоритет клиента; заполнены только известные | у значения источник «Из вашего сообщения»/файл; «Не указано» не равно нулю; изменение сохраняется, в разговоре появляется «Условия изменены — пересмотреть вывод?» |
| P1-05 Документы | имя, компания, дата добавления, состояние; действия «Открыть», «Удалить» | файл связывается с вопросом, из которого загружен; при неоднозначной компании агент уточняет принадлежность |
| P1-06 Просмотр файла | PDF/изображение; текст; DOCX с абзацами/таблицами; XLSX с листами и ячейками; ссылка из ответа ведёт к точному доступному фрагменту | подсветка только если координаты известны; иначе точная цитата и номер страницы, без выдуманной подсветки |
| P1-07 Итог | последнее предложение агента или зафиксированное решение, дата, условия, основания, неизвестное | пользовательская запись визуально отличается от предложения; «Изменить решение»; прежняя версия доступна по «История» |

Загрузка: для MVP PDF, PNG, JPG, TXT, MD, CSV, TSV, XLSX, DOCX, HTML, JSON, XML; до 10 МБ на файл, до 10 файлов на проверку — это принятые ограничения прототипа. Состояния: «Загружается» → «Читаю документ» → «Готово»; ошибки «Файл больше 10 МБ», «Формат не поддерживается», «Документ защищён паролем», «Не удалось прочитать текст» с повтором/удалением. Для нечитаемого файла предложить вставить фрагмент текстом. После удаления материала связанные выводы помечаются как требующие пересмотра. Инструкции внутри документов не становятся командами агенту.

### P1-08 — добавление компаний

В панели «Компании» кнопка «Добавить» открывает поле «ИНН или название» и многострочный ввод через «Добавить списком». По названию поиск выполняется только по доступной демо-базе: строка результата содержит название, ИНН и регион; пользователь выбирает нужное юрлицо. Точное совпадение ИНН позволяет сразу получить отчёт. При нескольких совпадениях по названию агент не выбирает компанию самостоятельно.

Для списка разделители — новая строка, запятая или точка с запятой. Под полем предварительный результат: «Добавятся: 3 · Уже есть: 1 · Ошибки: 1». Ошибочные строки перечислены с причиной; кнопка «Добавить 3 компании» добавляет валидные. При превышении лимита показывается «В проверке можно хранить до 20 компаний. Уберите лишние ИНН»; молча обрезать список нельзя. Внутри P1 доступно исключение компаний, затем повтор добавления. Для ИП принимается 12-значный ИНН, для юрлица — 10-значный; доступность отчёта зависит от набора, а не только от формата.

После добавления отчёт доступен сразу. Новая компания не меняет автоматически объект вопроса: в чате появляется «Компания добавлена» и две кнопки «Обсудить компанию» / «Сравнить с текущей» при наличии второй. Контекст ссылок всегда содержит компанию. Если пользователь пишет «у неё» при нескольких возможных адресатах, агент уточняет компанию.

### Изменение условий и незавершённая работа

При изменении условий пользователь видит прежнее и новое значение перед сохранением. После сохранения предыдущий вывод помечается «Сделан для прежних условий»; «Пересмотреть вывод» отправляет агенту задачу с изменением, «Позже» оставляет старый вывод с пометкой. Устаревшая рекомендация не может быть записана кнопкой одним кликом: D1 сначала показывает новые условия и предлагает пересмотр либо запись собственного обоснования.

При закрытии панели сохраняются её внутреннее состояние, черновик сообщения и позиция разговора. При уходе на другой проект незавершённая отправка не происходит автоматически. При отключении интернета поле остаётся редактируемым; «Отправить» недоступно с текстом «Нет соединения», повтор после восстановления — вручную. Закрытие страницы или переход в другую проверку не отменяет уже запущенную работу агента. При возвращении сначала показываются сохранённые материалы, затем текущий этап либо готовый ответ. Если агенту нужен ответ человека, показывается «Нужны сведения». Отдельная кнопка «Остановить» отменяет запуск. Это обязательное целевое поведение; техническая интеграция проверяется при реализации.

## 7. C1 — сравнение как дополнительный сценарий

Входы: S1-03; кнопка «Сравнить» в S2; сообщение «Добавь ещё две компании и сравни условия». Все ведут в текущую проверку и выбранный чат, историю и условия сохраняем. При одной компании кнопка сравнения скрыта; запрос текстом вызывает просьбу добавить вторую.

| ID / элемент | Что рисовать | Поведение и приёмка |
|---|---|---|
| C1-01 Выбор | список компаний проекта с Checkbox, «Добавить по ИНН» и «Сравнить выбранные» | от 2 до 20 выбранных; дубликаты не добавляются; одна ошибочная компания не отменяет остальные |
| C1-02 Цель | строка «Сравнение для: [цель]» + «Изменить» | берётся из проекта; если цели нет, доступно базовое сравнение фактов, агент отдельно уточняет задачу |
| C1-03 Таблица | компании по строкам; столбцы: название/ИНН, риск банка, финансовый контекст, действующие взыскания, условия предложения, что не подтверждено | закреплён первый столбец; вертикальная прокрутка до 20 строк; условия предложения берутся только из пользовательских материалов |
| C1-04 Раскрытие | ссылка в ячейке/кнопка «Основание» | внутри той же панели показывает P1-03; «К сравнению» возвращает выбранные компании, сортировку и скролл |
| C1-05 Вывод | над таблицей краткое объяснение агента относительно цели; кнопка «Обсудить сравнение» | сворачивает панель и прикрепляет ссылку на сравнение в composer, без автоотправки |
| C1-06 Отбор | Checkbox строк + «Продолжить с выбранными» | отмечает кандидатов для дальнейшего обсуждения; не удаляет остальные отчёты из проекта |

Нет нового сводного балла и автоматически назначенного победителя. Агент может обосновать предпочтение и условия выбора. Факты считаются кодом; объяснения явно помечены как ответ помощника. Отсутствующие условия показываются «Не указано», а не как худшая цена/срок. Сравнение разных дат среза сопровождается примечанием. Пять компаний демонстрируются обязательно; отдельный макет на 20 подтверждает масштабирование. Основной разговор должен оставаться полезным без сравнения.

## 8. D1 — записать решение и продолжить после новых данных

| ID / элемент | Что рисовать | Поведение и приёмка |
|---|---|---|
| D1-01 Выбор | Radio: «Готов работать», «Готов при условиях», «Не готов работать», «Нужно больше сведений» | ни один вариант не выбран за человека; предложение агента выше отдельным текстом |
| D1-02 Обоснование | редактируемое поле «Почему»; ниже условия/нужные сведения | можно принять предложенный текст или изменить; для вариантов с условиями/неизвестным нужна хотя бы одна конкретная запись |
| D1-03 Сохранение | «Записать решение»; «Вернуться к разговору» | сохраняет автора, дату, выбранные компании, версию оснований; статус «Решение записано», кроме «Нужно больше сведений» → «Нужны сведения» |

Пользователь может записать несогласие с рекомендацией. Система не проводит платёж, не отправляет запрос поставщику и не обещает юридическую гарантию. Кнопка «Скопировать вопросы» копирует текст; отправка пользователем происходит вне MVP.

## 9. Реальные границы данных и копирайтинг

Выгрузка содержит 100 отчётов с неодинаковыми разделами. У 67 есть финансы, у 9 — лицензии, у 30 — проверки ведомств, у 8 — сведения о закупках. У 61 перечислены связанные компании, но полные отчёты внутри выборки есть лишь для одной взаимосвязанной пары. Арбитраж преимущественно агрегирован: нельзя рисовать несуществующие тексты решений и предметы дел. Предыдущий запрет на показ любых лицензий был ошибочным; в v2 показываем имеющиеся записи, отсутствие — как отсутствие сведений.

| Ситуация | Текст/представление | Недопустимое впечатление |
|---|---|---|
| Банковская оценка | «Риск по оценке банка»; цвет и текст согласно исходной шкале; пояснение «Не заменяет оценку финансового положения» | зелёный = гарантия надёжности |
| ЗСК | отдельная строка «ЗСК» с раскрываемым пояснением; только зелёный или серый по подтверждённому отображению | новый красный/жёлтый ЗСК |
| Несоответствие сырых значений ЗСК | в fixture встречаются GREEN/YELLOW/RED; исходные данные сохраняются; пока нет подтверждённого маппинга, для YELLOW/RED нейтральное «Отображение требует уточнения» | молчаливая замена значения и ложное объяснение серого |
| Действующие взыскания | число, известная сумма, дата, пропуски; вывод зависит от масштаба и задачи | любое взыскание — запрет на сотрудничество |
| Отрицательный капитал | отдельный факт и объяснение в контексте | банкротство как автоматически установленный факт |
| ОКВЭД | код вместе с текстом деятельности; спорные исходные пояснения не копируются как истина | число кодов доказывает недобросовестность |
| Проверено, записей не найдено | «В отчёте события не обнаружены» | «Событий никогда не было» |
| Блок не предоставлен | «В отчёте нет этих сведений» | зелёная галочка или ноль |
| Ограничение доступа | «Эти сведения недоступны» | притворное отсутствие риска |
| Возраст данных | всегда дата среза/период; после 30 дней нейтральное «Срез старше 30 дней» как правило прототипа | обещание обновления из живых реестров при статическом mock |
| Рекомендация AI | «По доступным сведениям…», основания, что может изменить вывод | «Альфа гарантирует», «Компания мошенническая» |

Даты отчётности и дата проверки не смешиваются. Балансовые деньги за 2025 год не подписываются «Сейчас на счетах». Для отношения сумм к капиталу при нулевом/отрицательном знаменателе нет обычного процента и ранжирования «лучше/хуже». Флаг ОКВЭД не пересчитывается моделью по числу кодов. Первичные ссылки показываются только при наличии реального источника.

## 13. X1 — внешний AI, опциональное приложение

Один дополнительный экран, ссылка «Подключить своего помощника» в меню проверки. Показывает конкретного получателя, выбранную проверку, разрешённые категории данных, режим «Только просмотр», срок и отзыв доступа. Кнопки «Разрешить подключение» и «Отмена». Демонстрационная авторизация явно помечена; не изображать production-подключение завершённым. Закрытые данные контрагента и неразрешённые поля не предлагаются в переключателях. Пользовательские файлы по умолчанию исключены из внешней передачи. X1 не нужен для прохождения F01–F13. Внутренний MCP остаётся технической реализацией действий агента и не показан в основном UI.

## 14. Передача в работу и приёмка

## 16. Готовая основа чата и новые состояния фоновой работы

Для разработчика согласованы assistant-ui и Python assistant-stream. Дизайнер проектирует визуальные композиции на Core DS, используя обычные паттерны ленты сообщений, composer, карточек действий, загрузки файлов и восстановления. Внешний вид не обязан совпадать с демо assistant-ui. Не рисовать отдельный сложный интерфейс выполнения графа.

| ID | Дизайн-требование | Что передать |
|---|---|---|
| R11 | Работа продолжается после ухода | Дополнительные фреймы F14: уход во время проверки; F15: возвращение к работающему агенту; F16: возвращение к готовому результату |
| R12 | Отключение и отмена различаются | E09 — потеря связи; E05 — явная остановка; тексты и доступные действия различаются |
| R13 | Вопрос пользователя не теряется | При недоступном соединении черновик остаётся; после reconnect исходное сообщение не отправляется второй раз |
| R14 | Наблюдаемость не равна показу рассуждений | Один текущий этап, раскрываемые завершённые действия, ссылки на основания; никакого chain-of-thought и сырого JSON |

F14–F16 обязательны дополнительно к F01–F13. В UI нет технических названий библиотек и слова RPC. После возвращения пользователь различает: «работает», «нужен мой ответ», «результат готов», «прервано». Это состояния текущей работы; общий статус проекта «В работе / Нужны сведения / Решение записано» сохраняется и не превращается в риск-светофор.

## 17. Условия передачи дизайнером

Помимо Figma-фреймов передать таблицу компонентов (element ID → Core DS component / custom composition → состояния), кликабельные переходы, адаптив и список использованных официальных иконок. К каждому сложному элементу приложить пример данных: номер источника, дата отчётности, отсутствующее значение, предложение агента и запись пользователя. Новые композиции допускаются для ответа, ссылки на источник и результата; базовые кнопки/поля/панели остаются компонентами Альфы.

## 18. Дополнение 3.1: несколько чатов и прикрепление артефактов

Это обновление существующего ТЗ; S1/S2/P1/C1/D1 и все прежние ID сохраняются. Проект на UI называется «Проверка», сессия внутри него — «Чат». Не добавлять третий главный экран. Сохраняемый чат — рабочая сессия, не сеанс входа в банк.

| ID | Элемент / точный текст | Действие и состояние |
|---|---|---|
| S2-13 | «Чаты» и «Новый чат» в компактной навигации проекта | Переключение внутри S2; новый чат получает общие подтверждённые условия, история другого чата не подмешивается |

На desktop список чатов — компактная колонка/раскрытие в пространстве проекта, не ещё одна постоянная широкая панель рядом с банковской навигацией и материалами. Default ширина списка 220 px; при открытой панели материалов список сворачивается в переключатель в шапке. На mobile — отдельное полноэкранное меню чатов, после выбора возвращает в S2. Draft и attachments сохраняются отдельно для каждого чата.

Дополнительные кадры: F17 — два чата одного проекта, один продолжает работу; F18 — выбор артефакта прошлого чата и отправка в новом; F19 — чтение XLSX через skill с листом и ячейкой; F20 — DOCX с неопределённым сроком; F21 — follow-up «Аванс уже снизили до 20%» во время tool call, затем подтверждение, что новое условие учтено. Макеты используют Core DS (PureCell, Menu/доступный popover composition, Tag, Table, Textarea, Button), поведение чата — assistant-ui.

Старые .doc/.odt/.rtf: показывать поддержку только при доступном конвертере; иначе «Сохраните документ как DOCX или TXT». Факт добавления Word/XLSX не означает поддержку макросов, редактирования всех формул и юридической экспертизы договора. Фокус — прочитать, сослаться и обсудить существенное условие.

Приёмка дополнения: переключение чатов не смешивает историю; артефакт прикрепляется с версией; skill trace появляется по факту вызова; follow-up принят до окончания инструмента и влияет на следующий ответ; запрос не дублируется после reconnect.
