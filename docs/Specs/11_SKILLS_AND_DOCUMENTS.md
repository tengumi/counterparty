# 11. Skills и работа с документами

Версия 1.1 · 05.09.2026. [Индекс](00_OVERVIEW_AND_INDEX.md) · [Контракты](10_SYSTEM_CONTRACTS.md) · [Дизайн](07_DESIGN_AND_UX.md).

## 1. Результат для пользователя

Пользователь прикрепляет КП в XLSX, договор в DOCX или материал проекта к сообщению. Агент выбирает подходящий навык, читает нужные части, уточняет неоднозначные условия и обновляет анализ. В чате видны реальное действие, результат и ссылки на документ. Несколько чатов проекта имеют отдельную историю; материалы доступны по явным ссылкам, без автоматического добавления всех разговоров в контекст.

Это спецификация интеграции. Выбранные навыки и библиотеки ещё необходимо подключить и проверить в приложении; наличие этого файла не означает готовую реализацию.

Использовать готовые инструкции и необходимые файлы конкретной папки, закрепить commit, сохранить attribution. Не загружать весь каталог навыков. Изменения интеграции версионировать отдельно от upstream. При реализации проверить доступность закреплённого пути; при переносе репозитория обновлять lock осознанно.

[Deep Agents поддерживает skills и постепенную загрузку инструкций](https://docs.langchain.com/oss/python/deepagents/skills). Использовать этот механизм для обнаружения и загрузки навыка. SkillExecutor — прикладная граница разрешённых операций и trace, а не собственная замена agent loop. Если инструкция требует запуска скрипта, её исполняет заранее разрешённый адаптер. Наличие текста SKILL.md само по себе не даёт агенту shell, сеть или доступ ко всем файлам.

## 3. Форматы и точные ссылки

| Формат | Что извлекаем | Ссылка в UI | Исполнение |
|---|---|---|---|
| XLSX | Листы, диапазоны, значения, единицы, заголовки; формулы и доступные cached values отдельно | Имя листа и диапазон A1; открыть нужные строки | fastexcel для native чтения; дополнительный форматный адаптер для формул/координат |
| DOCX | Абзацы, заголовки, таблицы, условия и реквизиты | Абзац либо таблица/строка/ячейка | MarkItDown и готовые DOCX/OOXML readers, без собственного полного Word renderer |
| PDF | Текст и страницы; OCR/vision при необходимости | Страница и фрагмент | PDF skill; execution policy зависит от библиотеки |
| TXT, MD, CSV, TSV | Строки и структурированные значения | Строки или диапазон таблицы | Ограниченное чтение готовыми библиотеками |
| HTML, JSON, XML | Текст либо структурированные поля | Фрагмент/путь, привязанный к исходнику | Без исполнения HTML/JS и загрузки внешних XML entities |
| PNG, JPEG | Распознанный текст и область изображения | Изображение/область | Настроенный OCR/vision adapter с явной ошибкой при недоступности |

DOC, ODT и RTF — дополнительная поддержка через установленный конвертер, например LibreOffice в отдельном процессе. Если его нет, UI показывает неподдерживаемый формат; MVP не обещает чтение любого документа.

Markdown после конвертации полезен для обзора, но недостаточен как единственный источник XLSX evidence. Сохранять координаты отдельно. Не выполнять макросы, внешние ссылки и формулы. Cached value не является свежим пересчётом: показывать доступность и происхождение, не подставлять 0 при отсутствии. Не придумывать страницы DOCX: пагинация зависит от renderer. Скрытые строки и листы не терять молча — учитывать в extraction metadata.

## 4. Потоки и GIL

Блокирующие операции не выполняются внутри event loop. Предпочтительный путь — bounded thread pool для потокобезопасного native участка с подтверждённым release GIL. Для Python-heavy conversion или непотокобезопасной библиотеки использовать ограниченный process executor. Это локальное исполнение библиотеки, отдельный микросервис не нужен.

- В [исходниках fastexcel](https://github.com/ToucanToco/fastexcel/blob/main/src/lib.rs) открытие reader использует `py.detach`. Это подтверждение конкретного участка, а не обещание освобождения GIL на всей цепочке или безопасности общего reader между потоками. Каждый job получает свой reader; поведение закреплённой версии проверяется.
- [lxml освобождает GIL при parsing](https://lxml.de/FAQ.html); использовать собственный parser на поток. Python-обход DOCX и преобразование результатов могут снова удерживать GIL.
- [PyMuPDF не поддерживает многопоточное использование](https://pymupdf.readthedocs.io/en/latest/recipes-multiprocessing.html). При выборе этой библиотеки использовать процессы.
- MarkItDown целиком не считать GIL-free. Обёртка `to_thread` сама по себе не делает Python CPU-код параллельным. Отмена ожидания thread не гарантирует остановку native-вызова; для принудительного timeout нужен процесс.

Использовать штатный executor/offload фреймворка, ограничить concurrency, не создавать новый pool на каждый запрос. Сохранить лимиты загрузки из 03; дополнительно ограничить размер распакованного Office-архива и извлекаемых фрагментов. Большие листы читать диапазонами; не помещать всю книгу в prompt.

## 5. Путь исполнения и trace

1. UI загружает файл через REST. Backend проверяет размер, MIME, project scope и hash; это техническая подготовка, не применение навыка.
2. Сообщение ссылается на document_id или конкретную версию артефакта. Агент определяет, что нужно узнать для вопроса пользователя, и загружает готовый skill.
3. SkillExecutor запускает разрешённую операцию reader. Кэш определяется hash файла, версией reader, параметрами и операцией. Попадание в кэш отображается честно.
4. Сохраняются фрагменты, locators, предупреждения и input/output refs. Агент получает обзор и выбирает нужные диапазоны; исходный файл остаётся доступен через evidence.
5. Агент учитывает результат и queued уточнения пользователя перед следующим обращением к модели. Новый вывод получает версию; прежний не переписывается незаметно.

Внутренние события: `skill.started`, `skill.completed`, `skill.failed`, `skill.cancelled`; поля SkillInvocation находятся в 10. На UI они проходят через общий activity stream, без отдельного транспорта.

Публичная подпись: «Использую навык „Чтение документов“» или «Использую навык „Чтение PDF“». Для операции XLSX допустимо «Использую навык „Чтение таблиц“»: это display name операции markitdown, не выдуманный upstream skill. После завершения: «Прочитал условия оплаты — лист „КП“, B8:D12». Не показывать такое событие до фактического старта. Пользователю не нужны пути скриптов, модельные рассуждения или технический каталог навыков.

## 6. Демонстрация и приёмка

Синтетический пример: в чате «Условия поставки» пользователь прикрепляет КП, где цена 2,4 млн ₽ и аванс 80%. Агент читает конкретные ячейки, рассчитывает аванс 1,92 млн ₽ и спрашивает про условие возврата. Пока читается DOCX, пользователь отправляет: «Договорились на 20%, учти». Сообщение сразу появляется как принятое; после завершения текущего инструмента агент учитывает 480 тыс. ₽, сопоставляет новое сообщение с прежними условиями документа и уточняет, оформлено ли изменение. Итог не объявляется согласованным условием договора только на основании сообщения.

В другом чате этого проекта пользователь прикрепляет сохранённый анализ: ссылка фиксирует его версию, история первого чата не копируется. UI показывает доступные материалы и позволяет открыть доказательства.
