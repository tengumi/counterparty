## Готово

- Самостоятельный uv-проект `services/agent` (Python 3.13, hatchling,
  локальная зависимость `counterparty-contracts`).
- `config.py`:настройки окружения через pydantic-settings, DSN как `SecretStr`.
- `composition.py`: lifespan-фабрика с внедряемой фабрикой checkpointer —
  внешние ресурсы открываются только на старте, не при импорте.
- `checkpointing.py`: тонкая граница вокруг штатного `AsyncPostgresSaver`;
  собственный checkpoint engine не пишется, schema setup исключён (миграции —
  шаг деплоя, а не работа воркера).
- FastAPI `/healthz` без обращения к внешним зависимостям.
- Собственный Dockerfile: build context — корень монорепы, venv собирается по
  финальному пути `/app/.venv`, запуск от непривилегированного пользователя.

## Migration proposal (для будущего владельца DB-01)

`migrations/**` не менялись. LangGraph PostgreSQL checkpointer требует
собственных таблиц; предложение:

- выделить отдельную схему (например `agent_state`) под checkpoint-таблицы
  LangGraph, не смешивая их со схемами `reports` и `workspace`;
- создавать таблицы шагом деплоя (Alembic-ревизия либо разовый
  `AsyncPostgresSaver.setup()` в отдельной job), но не при старте воркера —
  сейчас код это сознательно не делает;
- зафиксировать версию `langgraph-checkpoint-postgres`, поскольку DDL
  принадлежит библиотеке, а не проекту.
