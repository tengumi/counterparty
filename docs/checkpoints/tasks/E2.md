## Решения и допущения

- «Что проверено» показывает только завершённые шаги: раздел отвечает на
  вопрос, что уже сделано, а не что модель думает сейчас. Текущий шаг остаётся
  строкой хода работы.
- Тест на шаги утверждает внутри списка, которым владеет нажатая кнопка (через
  `aria-controls` + `within`), а не по всему экрану: один и тот же источник
  («Отчёт · срез 5 августа 2026») встречается у нескольких шагов.
- Terminal error и отмена во время run проверяются на двух уровнях: транспорт
  end-to-end в `src/chat/transport.test.tsx` (C1, фикстуры Python-энкодера), а
  презентационный контракт — в `conversation/Composer.test.tsx`. Дублировать
  SSE-стрим в тестах S2 не стал.
- Варианты ответа и «Обсудить» только заполняют composer и никогда не
  отправляют сами; вставка дописывается к уже набранному тексту.
- Черновик, прокрутка и состояние панели живут в `localStorage` как удобство
  одного зрителя; ключ включает id проекта и чата, чтение обёрнуто в try/catch,
  пустой черновик игнорируется, чтобы задача из S1 выигрывала.
- Панель — одна поверхность со стеком глубиной не больше двух: список → элемент.
  Всё, что глубже, отложено до WEB-06.
- Выравнивание с референсным макетом сознательно не трогал — это WEB-07.

## Ограничения / стыки на волну G

- Источник блоков разговора — `getConversation(chatId)` из моков; замена на REST
  (`GET /threads/:id/messages`) не должна менять компоненты: union
  `ConversationBlock` — граница.
- `getMaterials(projectId)` и `findEvidence(id)` так же ждут REST; основание
  сейчас разрешается локально, при живом API это ответ сервиса отчётов.
- Отправка в не-демо чатах, сохранение черновика на сервер и состояние
  «Сохранено» в шапке — заглушки; живой транспорт есть только у демо-чата.
- Отмена запуска использует команду cancel рантайма C1; для чатов без живого
  треда состояние `cancelling` пока недостижимо.
