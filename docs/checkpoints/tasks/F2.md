## Готово

- `services/ui_api` подключён к `packages/storage`: engine открывается в
  lifespan, каждый запрос получает один tenant-scoped `AsyncUnitOfWork`,
  ownership читается реализацией порта `StorageProjectDirectory` (порт и
  зависимости из API-01 не менялись). Без `UI_API_DATABASE_URL` сервис
  отдаёт health/session, а проектные маршруты — `dependency_unavailable`.
- API-02: `POST /api/v1/projects` (создаёт project + первый thread + ставит
  `default_thread_id` в одной транзакции), `GET /api/v1/projects` (cursor
  pagination, только свои проекты), `GET/PATCH /api/v1/projects/{id}`.
  Rename не двигает `context_version`.
- Идемпотентность создания — поверх `workspace.idempotency_keys` и
  `IdempotencyRepository` (второй реализации нет): повтор с тем же payload
  отдаёт первый проект `200 + idempotent-replay: true`, параллельный запрос
  получает `409 conflict` `details.reason=request_in_flight` `retryable=true`,
  тот же id с другим payload — `409 conflict`
  `details.reason=request_id_reused`. Неудачная попытка освобождает
  резервацию, иначе retry был бы навсегда отвергнут.
- API-03: `GET /api/v1/companies` (локальный поиск по ИНН/подстроке, cursor),
  `POST /api/v1/projects/{p}/companies` (per-item added/already_present/
  not_found/invalid, закрепление конкретного `report_id`, batch целиком
  отвергается при выходе за 20), `DELETE /api/v1/projects/{p}/companies/{c}`
  (`removed_at`, история и снапшот сохраняются, `context_version` растёт).
- Демо-личности из конфигурации создаются в `workspace` при старте
  (idempotent upsert), иначе сессия не смогла бы владеть проектом.

## Решения и допущения

- Повтор создания отвечает `200` + заголовок `idempotent-replay`, первый —
  `201`: клиент должен уметь отличить replay от создания.
- Резервация коммитится до работы. Только так возможен честный ответ
  «запрос уже выполняется»; цена — освобождение ключа при сбое и риск
  «зависшей» резервации при жёстком падении процесса.
- Список проектов фильтруется по владельцу в `reads.load_owned_projects`:
  `ProjectRepository.list_recent` фильтра владельца не имеет, а показывать
  проект, который нельзя открыть, хуже дублирования запроса.
- Компания без имени в отчёте показывается под своим ИНН; имя не выдумывается
  и компания не скрывается.
- Компания без единого снапшота — `invalid` + `source_missing`: закреплять
  нечего, а отсутствие данных не означает отсутствие риска.
- Тесты идут под ролью владельца БД, поэтому привилегии `counterparty_ui_api`
  здесь не перепроверяются: это предмет `migrations/tests` из E1.
