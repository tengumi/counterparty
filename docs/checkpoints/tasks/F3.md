## Решения и допущения

- Отдельной поверхности отчёта нет: это экран `company` того же стека WEB-05.
  Первоисточник основания — третий уровень стека, а не новая панель.
- Раздел и строка — разные уровни незнания: раздел может отсутствовать целиком
  (`availability`), строка внутри доступного раздела — быть missing/empty/
  unavailable. Поэтому у Урал-Восток «Финансы» помечены как отсутствующий
  раздел, а не как набор пустых строк.
- Числа взяты из записей снапшота 7449088645 (Компания А), 5029069967
  (Урал-Восток: нет финансовых отчётов, `riskLevel: UNKNOWN`, срез 29.07.2026 →
  старше 30 дней) и 7728380537 (Транс-Лайн: `zskRiskLevel: YELLOW`). Для
  логистических компаний сохранены их учебные названия и ИНН из моков E2, из
  снапшота взята только форма значений — это допущение мока, а не утверждение
  о реальных юрлицах.
- Состояние `unavailable` в выгрузке не размечено: строка «Сведения о
  бенефициарах» и раздел «Другие сведения» у Транс-Лайн помечены ограничением
  доступа как мок, чтобы состояние было видимо и проверяемо. При живом API
  источником этого состояния должен стать ответ сервиса отчётов.
- Демо-ответ чата обновлён под значения отчёта (капитал −300 000 ₽, 12
  завершённых производств, регистрация 2009). Иначе одна и та же компания имела
  бы два разных капитала — прямое нарушение правила о разрешении значений.
- Раскрытие разделов хранится в локальном состоянии экрана отчёта, а не в
  `persisted.ts`: панель по-прежнему запоминает открытость и стек, а раскрытые
  разделы отчёта — удобство одного просмотра.
- Внешний вид (сетка, типографика, цвета) сознательно не выравнивался: это
  WEB-07. Точки-индикаторы отмечают состояние, а не вердикт.

## Ограничения / стыки на волну G

- `getCompanyReport(companyId)` и `findEvidence(id)` — граница замены на REST.
  Компоненты видят только `CompanyReport` / `EvidenceRecord`, поэтому подключение
  сервиса отчётов не должно менять `CompanyReport.tsx` и `reportView.ts`.
- `EvidenceRecord.documentId` ждёт реальный `document_id`; сейчас у него есть
  ровно один держатель (`ev-offer`), просмотр содержимого файла — P1-06.
- `bankRiskRaw` / `zskRaw` приходят строками ровно так, как в снапшоте
  (`riskLevel`, `zskRiskLevel`). Маппинг ЗСК на отображение остаётся открытым
  решением: подтверждён только GREEN.
- Состояния `unavailable` и `asOfStale` сейчас декларируются моком; API должен
  сообщать их явно, иначе UI не сможет отличить ограничение доступа от
  отсутствия блока.
